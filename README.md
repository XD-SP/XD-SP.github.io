# 订单号查询页（GitHub Pages）

输入订单号，自动匹配 `orders/` 目录下的 HTML 文件名并打开对应订单页面。
文件名就是订单号，不需要维护数据库或表格。

## 文件结构

```
.
├── index.html                                  # 查询首页（部署后用这个地址访问）
├── orders/                                      # 订单 HTML 存放目录
│   ├── DD20261012001.html                       # 文件名 = 订单号
│   ├── DD20261012002.html
│   ├── index.json                               # 自动生成的清单，不用手改
│   └── ...
├── scripts/gen-index.js                         # 生成清单的脚本
├── .github/workflows/update-order-index.yml     # 推送后自动重建清单
└── README.md
```

## 本地预览

必须用本地服务器打开，直接双击 `index.html` 会因为浏览器安全限制读不到清单：

```bash
cd 项目目录
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

没有 Python 也可以用：

```bash
npx serve .
```

## 线上地址

```
https://xd-sp.github.io/
```

仓库是 `XD-SP/XD-SP.github.io`（即 GitHub 用户主页仓库），Pages 已开启，
从 `main` 分支根目录发布，推送后 1–2 分钟生效。不用再做任何配置。

## 上传订单文件

最常用的方式，不用装 Git、不用懂命令行：

1. 打开 `https://github.com/XD-SP/XD-SP.github.io`，进 `orders/` 目录
2. 点右上角 **Add file → Upload files**
3. 把订单 HTML 拖进去，拉到底点 **Commit changes**
4. 等约 1 分钟，GitHub Actions 会自动重建清单，微信里刷新就能查到

也可以用命令行：

```bash
git add orders/
git commit -m "新增订单"
git push
```

清单由 `.github/workflows/update-order-index.yml` 自动生成。
这里有两个防坑设计：工作流自己推送的提交**不会再次触发**（`if: github.actor != 'github-actions[bot]'`），
否则会因为清单里的时间戳每次都变而陷入无限循环提交。

## 命名规范

- 文件名即订单号，例如 `DD20261012001.html`
- 支持 `.html` / `.htm`
- 不要用 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 这些字符
- 查询时忽略大小写、`-`、`_`、空格，所以 `DD-2026-1001` 和 `dd20261001` 都能搜到同一个文件

## 页面功能

| 功能 | 说明 |
| --- | --- |
| 模糊搜索 | 输入订单号的任意连续片段即可，例如 `1002` |
| 精确直达 | 完全匹配时自动跳转到订单页 |
| 自动补全 | 输入时出现候选下拉，↑↓ 选择、回车打开 |
| 本页查看 | 不新开标签页，直接嵌在下方面板里看 |
| 最近查询 | 自动记住最近 8 条，本地保存 |
| 直达链接 | `https://xd-sp.github.io/?q=DD20261012001` |
| 深浅色切换 | 右上角按钮，记住选择 |

## 微信里怎么打开

页面已按微信内置浏览器的限制做过适配，把这个网址直接发出去即可：

```
https://xd-sp.github.io/
```

也可以在微信里发直达某个订单的链接：

```
https://xd-sp.github.io/?q=DD20261012001
```

已处理的微信兼容问题：

| 问题 | 处理 |
| --- | --- |
| 微信拦截 `window.open` 弹窗 | 结果一律用真正的 `<a>` 链接；精确命中时走当前页跳转 |
| 微信缓存极重，更新订单后还显示旧内容 | 链接自动带 `?v=` 版本号，取自清单的 `generatedAt`，重建清单即主动失效缓存 |
| 自动识别手机号/邮箱导致样式错乱 | 加 `format-detection` 关掉自动识别 |
| iOS 点击输入框自动放大 | 输入框字号 16px 以上 |
| 分享到聊天时的标题描述 | 配了 og 标签 |

**三个要留意的点：**

1. **免费版 GitHub Pages 只有公开仓库能用**，页面和数据任何人都看得到。含客户姓名、电话的敏感订单别直接公开。
2. `github.io` 在国内部分地区访问不稳定，微信里偶尔会慢或打不开。要求稳定的话建议换成国内托管 + 已备案域名。
3. 以后若要绑自己的域名，面向中国大陆提供服务需要 ICP 备案，否则可能被拦截。

## 需要改配置时

打开 `index.html`，最前面的 `CONFIG` 就是全部可调项：

```js
var CONFIG = {
  orderDir:   'orders/',            // 订单目录
  manifest:   'orders/index.json',  // 清单路径
  exts:       ['.html', '.htm'],
  maxRecent:  8,
  maxSuggest: 12
};
```

## 注意

- **用完示例订单记得删**：`orders/DD20261012001.html`、`DD20261012002.html`、`DD20261012003.html` 是演示文件，正式上线前删掉。
- **免费版 GitHub Pages 只有公开仓库能用**，订单数据如果涉及客户信息（姓名、电话、地址），公开等于对外泄露。这种情况别用免费 Pages，改用私有方案：内网静态服务器、企业版 GitHub、或加一层登录鉴权。
- 没有清单文件时页面不会崩，会自动切成"直连探测"模式（按文件名逐个试），但体验和准确率都差一些，建议跑一次生成脚本。
- 页面每次最多展示 60 条结果。
