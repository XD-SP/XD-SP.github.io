# 订单查询页（GitHub Pages）

扫板件条码或输入订单号，定位到订单后选择查看 **3D 模型** 或 **爆炸图**。
手机上可直接调用摄像头扫码，车间用 USB 扫码枪即插即扫，都能用。

线上地址：**https://xd-sp.github.io/**

---

## 一、上传订单（日常唯一要做的事）

### 推荐：双击 `一键上传订单.bat`

这一个动作完成两件事：从同步盘导入订单 → 上传到 GitHub → 约 1 分钟后网站自动更新。

首次使用前确认两件事：

1. 项目根目录有 `token.txt`（里面一行 GitHub Token）。该文件已在 `.gitignore`，不会被上传。
2. `sync-source.txt` 里写的是你的订单根目录，默认 `E:\同步盘`。路径改了就编辑这个文件。

脚本会自动完成：只传新增和改动过的文件、跳过没变的、同名文件直接覆盖。

> 走的是 GitHub 接口，**不需要本机 Git**，也不依赖 `github.com` 能否连通。

### 备选：GitHub 网页拖拽

```
https://github.com/XD-SP/XD-SP.github.io/upload/main/orders
```

把整个订单文件夹拖进虚线框（必须拖，点按钮选不了文件夹）。有三个限制：

| 限制 | 数值 |
| --- | --- |
| 单次文件数 | 100 个（一个订单约 25 个文件，最多同时拖 3–4 个订单） |
| 单文件 | 25MB |
| 同名文件 | **不能覆盖**，图纸返工重传会失败 |

所以长期用还是推荐上面的脚本。

### 清理已下线订单

在 `orders/` 里删掉对应文件夹，然后带参数调用脚本：

```bash
node scripts/publish.js --prune
```

不加 `--prune` 时脚本只增不改不删，避免误删线上文件。

## 二、订单目录规范

`orders/` 下**每个一级子目录就是一个订单，目录名就是订单号**：

```
orders/
├── index.json                                    ← 自动生成，不要手改
└── SZD261007003_005/                             ← 订单号
    ├── 3DHTML/
    │   └── viewer_SZD261007003_005.html          ← 3D 查看页
    ├── 爆炸图/
    │   ├── view_SZD261007003_005_00_全景装配.png
    │   ├── view_SZD261007003_005_01_全景爆炸.png
    │   ├── view_SZD261007003_005_02_柜0_装配.png
    │   └── view_SZD261007003_005_03_柜0_爆炸.png
    └── 板件编码对照_SZD261007003_005.csv          ← 板件明细
```

图片名规则 `<序号>_<分组>_<类型>.png`，其中：

- 分组：`全景`、`柜0`、`柜1`…
- 类型：`装配`、`爆炸`

`order_*.json` 不用传——`viewer_*.html` 已把 3D 数据全部内联，是自包含的。
正是它占了每个订单近一半的体积，导入脚本默认排除，四个订单就省了 1.78MB。

## 三、板件条码怎么定位订单

板件条码 = 订单号 + 尾部 4 位板件序号，所以**去掉后 4 位就是订单号**：

```
SZD261007003_0051001   ──去掉后4位──▶   SZD261007003_005
└──── 订单号 ────┘└尾┘
```

这是纯字符串规则，不需要维护任何对照表。扫到的条码还会去查该订单的 CSV，
显示这块板的**名称、柜体号、规格、花色**，并自动把爆炸图定位到它所在的柜体。

## 四、页面的三种输入方式

| 方式 | 怎么用 | 备注 |
| --- | --- | --- |
| 摄像头扫码 | 点「扫码」按钮，对准板件条码 | 需要 HTTPS；原生解码优先，不支持时自动加载 ZXing 引擎 |
| USB 扫码枪 | 插上直接扫，**不用点输入框** | 页面始终保持输入框聚焦，扫完自动回车查询 |
| 手动输入 | 键盘输入订单号 | 忽略大小写、`-`、`_`、空格 |

没摄像头或权限被拒时，页面会明确提示改用扫码枪或手动输入，不会白屏。

## 五、查到之后

命中订单后给出两个入口：

- **查看 3D 模型** — 打开 `viewer_*.html`，当前页跳转
- **查看爆炸图** — 按「全景 / 柜0 / 柜1…」分组浏览，点图看大图，支持左右滑动和键盘方向键

多笔订单匹配时列出清单，每条都带这两个入口。

直达链接：`https://xd-sp.github.io/?q=SZD261007003_005`

## 六、微信里能用吗

能，把网址直接发出去即可。已处理的兼容性问题：

| 问题 | 处理 |
| --- | --- |
| 微信拦截 `window.open` 弹窗 | 全程零 `window.open`，用真链接 + 当前页跳转 |
| 微信缓存极重，更新后还看旧的 | 链接自动带 `?v=` 版本号，重建清单即失效旧缓存 |
| 自动识别手机号导致样式乱 | 加 `format-detection` 关掉 |
| iOS 点输入框自动放大 | 输入框字号 16px |

## 七、清单是怎么自动生成的

`.github/workflows/update-order-index.yml` 在 `orders/**` 有变动时自动跑 `scripts/gen-index.js`，
扫描每个订单目录，把 HTML 路径、图片分组、CSV 路径写进 `orders/index.json`。

板件明细**不进清单**，而是保留原始 CSV，扫到条码时按需加载。
这样清单只有 11KB；订单涨到几百个时首屏也不会被拖慢。

工作流里的两个防坑设计：

- `if: github.actor != 'github-actions[bot]'` —— 否则机器人提交的清单会再次触发自己，无限循环
- 同一事件里不能同时写 `paths` 和 `paths-ignore` —— 写了整个 YAML 会解析失败，表现为「运行失败但没有任何 job」

## 九、脚本一览

| 文件 | 作用 |
| --- | --- |
| `一键上传订单.bat` | 双击运行：同步 + 上传一步到位 |
| `scripts/sync-local.js` | 把订单从源目录导入 `orders/`，默认排除 `order_*.json` |
| `scripts/publish.js` | 通过 GitHub 接口发布，`--prune` 时清理线上多余文件 |
| `scripts/gen-index.js` | 扫描 `orders/` 生成清单（线上由 Actions 自动执行） |
| `sync-source.txt` | 订单源目录配置 |
| `token.txt` | GitHub Token，已在 `.gitignore` |

## 十、要留意的三个风险

1. **免费 GitHub Pages 只能是公开仓库**，任何拿到网址的人都能打开全部订单。
   含客户姓名电话的敏感数据别这样放，改用内网部署或加一层访问密码。
2. `github.io` 在国内部分地区访问不稳定，微信里偶尔慢或打不开。
   要求稳定的话建议迁到国内托管 + 已备案域名。
3. 仓库超过 1GB 会收到 GitHub 提醒。按当前每个订单约 1.7MB 算，
   大约 600 个订单后需要考虑归档旧数据。
